# Cyber Resilience Act (CRA) statement

Short overview of how EventHorizon relates to the EU Cyber Resilience Act (Regulation (EU) 2024/2847) and which of its security practices it follows.

## Scope

EventHorizon is free, open-source software (MIT) developed by an individual, Kasper Back, without monetisation. The CRA applies to products made available in the course of a commercial activity, so EventHorizon is most likely outside its scope. The practices below are followed voluntarily.

## Product

| | |
| --- | --- |
| Product | EventHorizon, a macOS file shelf that lives in the MacBook notch |
| Manufacturer | Kasper Back (individual developer) |

| Supported version | The latest release only |

## Security by design

- **No data collection.** No accounts, telemetry, analytics or tracking.
- **Minimal network use.** The only network request is the optional update check to the GitHub API, which the user opts into on first launch and can turn off in Settings.
- **Local data only.** The shelf only holds references to files the user drops on it, in memory. Nothing is copied or uploaded, and the shelf is cleared on quit.
- **No third-party dependencies.** The app only uses Apple frameworks that ship with macOS (see the SBOM).

## Updates

- Security fixes are published as new GitHub releases.
- The in-app updater only installs a release whose zip has a valid Ed25519 signature from the developer's private key. The matching public key is built into the app. Unsigned or altered downloads are rejected and never installed.
- Releases are built only from the protected `main` branch, after the required CI tests have passed. Only the repository owner can create release tags.

## Software bill of materials (SBOM)

A CycloneDX SBOM (`EventHorizon.sbom.cdx.json`) is generated by CI on every push and pull request (downloadable as the `sbom` workflow artifact), and is attached to every release.

## Reporting vulnerabilities

Please report vulnerabilities privately through GitHub: **Security → Report a vulnerability** in the repository. Do not open a public issue for security problems.

Reports are acknowledged within 7 days. Confirmed vulnerabilities are fixed in a new release as soon as possible, and disclosed in its release notes once users can update.

## Known limitations

- The app is not notarized by Apple and is ad-hoc signed, so macOS shows an "unverified developer" warning on the first manual install. Updates installed from inside the app are verified with the developer's own signing key instead.
